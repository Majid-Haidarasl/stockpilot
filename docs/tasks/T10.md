## Context

Sales owns `Order` / `OrderLine` as an aggregate. This task builds the domain model, draft APIs if they can stand alone, and named status methods, without yet completing the shared transaction with inventory (T11).

## Exact scope

- `sales.orders` and `sales.order_lines`: status, version, customer, timestamps, frozen snapshot of title, SKU, and price at reserve time. Draft amounts are estimates from current catalog prices.
- Domain: named methods for reserve, confirm, cancel, expire, ship. Direct `status` assignment forbidden. Terminal states do not reopen. Max 20 unique product lines; line qty 1..100000.
- Draft: create, edit lines and customer, no stock effect, no reservation.
- After reserve (method-level): lines, customer, prices immutable; changes require cancel + new order. T11 performs the actual inventory call.
- Testable clock port for expiry (30 minutes). Scheduler **skeleton** and clock exist here so T14 does not rebuild expiry rules. No public expire HTTP route.
- `GET/POST .../orders`, `GET/PATCH .../orders/{id}` (PATCH draft only). Permissions: `sales` and `admin` write drafts; `viewer` read; `warehouse` does not commercially confirm (confirm is T11) and does not edit drafts.
- Money JSON strings; totals computed as sum(qty × frozen unit price) after reserve, estimate before.

## Files to create or touch

- Migrations for orders and lines (composite FKs to products/customers including `tenant_id`; no cross-module cascade delete)
- `sales` domain, application commands/queries, inbound routes for draft CRUD, `public.py`
- Domain unit tests for illegal transitions (e.g. cannot cancel shipped; cannot edit reserved lines)
- Clock port and a scheduler module skeleton

## Step-by-step implementation notes

1. Do not hydrate full aggregates for list views; a simple read path is allowed.
2. Cursor pagination `(created_at, id)`, max 100, allow-listed filters.
3. Leave hooks for `expected_version` and idempotency keys on mutating draft endpoints (T11 generalizes this).

## Acceptance criteria

- Drafts can be created and edited without reserving stock (scenario 2, at API/domain level).
- Illegal transitions are rejected in domain tests.
- Testable clock exists.

## Tests required

- Domain state machine (all legal and representative illegal transitions)
- Draft edit allowed; edit after reserved rejected at domain level
- Totals / money calculation
- Duplicate product line rejected; >20 lines rejected

## Out of scope

Full reserve/confirm/cancel/ship transaction (T11), Playwright, notifications worker.
