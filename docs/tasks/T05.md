## Context

Login and RLS are called out in the plan as complex and must work by the end of week 2 so fundamental mistakes are not found at the end of the project. This task implements real Keycloak login, PKCE, and a local server-side session. Organizational roles are **not** taken from Keycloak; they arrive in T06. Organization bootstrap (linking users) is required to demonstrate week-2 exit; the plan did not pin the bootstrap tool to a week — place a minimal audited `ops bootstrap` here or at the start of T06 (OPEN DECISION item 11: needed in week 2).

## Exact scope

- Add `keycloak` to Compose: operational settings, stable hostname, separate DB user, public login paths later via Caddy; do not expose the admin console publicly in production-like compose.
- One shared realm. Authorization Code + PKCE. FastAPI is the server-side of the UI: `GET /auth/login`, `GET /auth/callback`. Authlib validates the response. Allow-listed redirect URIs. Validate signature, issuer, audience, expiry, nonce. `state`, `nonce`, and PKCE data are one-time and short-lived.
- Create `access.sessions` and `access.login_attempts` (and any minimal user identity mapping needed) via Alembic. Store a **hash** of the session id, not the raw value. Cookie: `HttpOnly`, `Secure`, `SameSite=Lax`, host-scoped. Rotate session id after login. CSRF token + Origin checks on mutating routes such as logout.
- `GET /api/v1/me` returns session identity (organizations can be empty until T06). `POST /api/v1/auth/logout` invalidates the local session (CSRF-protected) and supports the standard Keycloak logout path.
- Tokens not in `localStorage` or JS-readable cookies. If stored for refresh/logout, encrypt server-side with a key **outside** the database. Refresh locked against double consumption.
- Idle 30 minutes, max 8 hours. Keycloak outage must not create or improperly renew sessions.
- Issuer URL identical for browser and API (stable name / DNS alias). Do not disable issuer checks.
- Frontend: login entry and post-login landing (org picker can be a stub until T06).

## Step-by-step implementation notes

1. Keep commercial routes unauthorized until a valid session exists (`401`).
2. Do not implement a product password store.
3. Log no tokens, cookies, or login bodies.
4. Tests must run in Compose with real Keycloak or a documented test doubles **only** if they still exercise the callback validation; prefer real Keycloak for the acceptance path.
5. Back-channel / global logout: do not claim it; document the window (OPEN DECISION 10).

## Acceptance criteria

- A user can log in through Keycloak and receive a server-side session; logout invalidates it.
- `/api/v1/me` works with a valid session and fails without one.
- Week-2 exit (with T06–T07): real login works; unauthorized users are rejected.

## Tests required

- Login and logout integration tests
- Session cookie flags / CSRF on logout
- Invalid callback (bad state/nonce/issuer) rejected

## Out of scope

RLS and membership CRUD (T06), catalog UI (T07), org admin role matrix beyond what login needs. No public registration.
