## Context

Week-1 exit requires that a **fresh clone**, using only Docker Desktop, Git for Windows, and Cursor on a **Windows 11** host, can start a sample API and a sample UI. Images stay Linux. This task creates the monorepo layout, dependency lock files, Dockerfiles, Compose files for the Phase 1 services, a FastAPI app with health endpoints, and a Persian RTL React shell. Patch versions are chosen by a compatibility test in this week and recorded; **do not invent them in advance**.

## Exact scope

1. Create the monorepo tree from `AGENTS.md` section 18, with empty-but-valid module packages (`access`, `catalog`, `sales`, `inventory`, `notifications`, `platform`, `bootstrap`) so Import Linter can be attached in T04.
2. Backend: `pyproject.toml` + `uv.lock`, Python 3.13, FastAPI, Pydantic, Uvicorn at minimum (SQLAlchemy, Alembic, Psycopg can be added here or completed in T03; if deferred, T03 must add them without reshaping the tree). A runnable API with:
   - `GET /health/live` — process is up
   - `GET /health/ready` — in T02 may report “not ready” without Postgres; T03 must make ready check Postgres + schema version. Prefer implementing the route shape now.
3. Frontend: Vite + React + TypeScript strict + MUI RTL shell. Persian layout direction, a suitable font setup, a placeholder home page (for example a title “StockPilot” and a short Persian subtitle). React Router can be present with a single route. TanStack Query, RHF, and Zod may be added now if versions lock cleanly, or in later UI tasks; do not add Next.js.
4. Dockerfiles:
   - Backend: official `python:3.13-…` base (exact patch **OPEN DECISION** until tested). Follow the [uv Docker guide](https://docs.astral.sh/uv/guides/integration/docker/). Multi-stage, `uv.lock` copied and installed in locked mode. Default command: Uvicorn. Do not use the deprecated official FastAPI image.
   - Frontend: Node.js **24 LTS** base (exact patch after test) for build and `frontend-dev`. Production `edge` image with Caddy can be a thin shell in this week or completed when Caddy routing is needed; Phase 1 may serve the UI via `frontend-dev` (Vite) so the sample UI “comes up”.
5. Compose:
   - `compose.yaml`, `compose.dev.yaml`, and a first `compose.prod.yaml` (may be minimal, using build or later-replaced image names; do not use `latest` as a release practice).
   - `.env.example` with non-secret placeholders only.
6. Record chosen major/minor tools and, after you actually install and test them in Docker, the patch versions and base-image digests in something like `docs/architecture/versions.md`. If a test cannot be completed because of network/registry issues, document that as a risk (plan section 28) rather than inventing pins.

## Step-by-step implementation notes

1. Scaffold folders exactly as section 18. Include `__init__.py` / package marks so imports work.
2. Create the backend project with uv **inside a container** (for example a one-shot `python:3.13` or official uv image). Never instruct the developer to install uv or Python on Windows (or Ubuntu). Do not require `make` on the host; if a helper script is needed, prefer a container command or a PowerShell `.ps1`.
3. Create the frontend with the Vite official React-TypeScript template **inside a Node 24 container**, then add MUI and RTL (`CacheProvider`, `ThemeProvider`, `direction: 'rtl'`, stylis-plugin-rtl or the current MUI-recommended approach). Configure Emotion cache for RTL, including portals. In the Vite config used by `frontend-dev`, set `server.watch.usePolling` to `true` so hot reload works on Windows bind mounts (default path `C:\\dev\\stockpilot` is fine; a WSL-filesystem clone is optional and advanced).
4. Keep commercial modules empty of business logic except perhaps a tiny placeholder used by T04’s sample domain test (or leave that test’s production code for T04).
5. Compose health: `depends_on` with `condition: service_healthy` for postgres once T03 adds a healthcheck. API should not need RabbitMQ.
6. Images run as a non-root user if practical already; full hardening is week 7, but do not bake in root-only patterns that week 7 must reverse.
7. Document AMD64 vs ARM: build and run the images on the developer’s Windows 11 machine (their architecture, usually AMD64) and note the result in `versions.md`. This addresses the week-1 risk in the plan. Images are still Linux.
8. If Compose cannot publish host port `5432`, document a host-port override and do not change the container port. Mention Docker Desktop memory (≥8 GB for the WSL engine) in the quickstart.
9. Project path in examples: `C:\\dev\\stockpilot` — no spaces, no Persian characters.

## Acceptance criteria (contributes to week-1 exit)

- A fresh clone on Windows 11 can build and start `api` and the frontend shell with Compose, with no Python or Node installed on the host.
- `/health/live` returns success for a running API container.
- The UI loads in the browser with a Persian RTL shell.
- `uv.lock` and `package-lock.json` are committed. Patch pins that were actually tested are recorded; untested patches are not invented.
- README quickstart has no hidden host steps and is PowerShell-safe.
