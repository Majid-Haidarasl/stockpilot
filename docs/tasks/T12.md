## Context

Week-5 exit: a sales user and a warehouse user can complete the main path in the Persian browser; stock and version errors are clear; basic admin pages work.

## Exact scope

- Pages: order list, draft form, order detail (status, allowed actions, frozen lines, reservation deadline + countdown as guidance only, change timeline).
- Limited dashboard: counts by status, sum of shipped amounts in a selected range, products below warning threshold.
- Member management page for `admin`: list members, change roles (last-admin rule visible).
- Error UX: insufficient stock shows product name and available qty; version conflict reloads and does not auto-resubmit; forbidden is in clear Persian; loading/empty/error/forbidden on all pages.
- Org switch and logout clear tenant-sensitive cache; query keys include `tenant_id`.
- No optimistic updates on reserve, ship, or inventory. Reuse `Idempotency-Key` on retry of the same action. Send `expected_version`. Money displayed as rial strings, not JS `number`.
- Keyboard access, labels, visible focus, desktop and ~390px, status not colour-only.
- Playwright e2e: real login, create order, reserve, confirm, ship, two-org isolation. Image version matches the Playwright package. Runs in Compose service `e2e` on the Docker network.
- Scenario 11: viewer cannot change inventory via direct API, and the UI shows the denial clearly.
- Cancel and expire must be demonstrable in the browser (expire may be shown after manipulating time/clock or waiting in a test, not by a public expire button unless it is an admin/ops affordance — the plan says no public expire endpoint; demonstrate via test clock or scheduler in a controlled test environment).
