## Context

StockPilot does not yet have a repository of product docs. Section 26 requires that ubiquitous language, order states, roles, and v1 constraints are frozen in product documentation, and that costly architecture choices are written as ADRs. This task produces those documents only. No application runtime is required yet, but the wording must be exact enough that later code, APIs, and tests copy the same identifiers.

## Exact scope

Create `docs/product/` and `docs/architecture/decisions/` content that a later agent can treat as the in-repo source of truth (still subordinate to `AGENTS.md` and the original plan).

Must include:

1. Ubiquitous language glossary: Persian term, English identifier, and the definition from the plan (`Tenant`, `Product`, `StockPosition`, `Draft`, `Reservation`, `Confirmation`, `Shipment`, `on_hand`, `reserved`, `available`, domain event vs integration event, `UnitOfWork`, etc.).
2. Roles and permission matrix: `admin`, `sales`, `warehouse`, `viewer`, including “last admin cannot drop their own role”, backend enforcement, and `404` for cross-tenant resources.
3. Order state machine: allowed transitions, terminal states, and the inventory-effect table (including reservation statuses `HELD`, `ALLOCATED`, `RELEASED`, `EXPIRED`, `CONSUMED`).
4. Business invariants (the ten rules), numeric caps, `IRR` / integer money, 30-minute reservation TTL, and v1 constraints (one warehouse, integer quantities, max 20 unique lines, complete shipment, no tax/discount/FX, no public signup or payment).
5. Explicit non-goals and postponed features (multi-warehouse, returns, accounting, legal invoices, real payments, public webhooks, attachments, heavy exports, specialised search, mobile app, advanced analytics; optional email).
6. ADRs, each with context, options considered, decision, and consequences:
   - `ADR-001` Modular monolith (required in week 1).
   - Also write first versions of `ADR-006` (sync SQLAlchemy vs async identity path), `ADR-007` (integer IRR and freeze-at-reserve), and `ADR-008` (single-server deploy limits), because these are foundation choices.
   - Create **stubs** (title + question only, status “proposed”) for `ADR-002` (shared order/inventory transaction), `ADR-003` (tenant isolation layers), `ADR-004` (opaque session), and `ADR-005` (Outbox/Inbox delivery contract). Those decisions are completed in the weeks that implement them — do not pretend they are fully decided in code yet, but do record the plan’s already-stated direction so later tasks do not drift.

## Step-by-step implementation notes

1. Copy identifiers and tables **faithfully** from `AGENTS.md` (which already follows the execution plan). Do not rename statuses or roles.
2. Include the numeric example: `on_hand=10`, reserve 3 → `10/3`, confirm unchanged, ship → `7/0`.
3. State that `available` is computed and not stored as an editable column.
4. Mark every **OPEN DECISION** from `AGENTS.md` section 27 in the product docs so they stay visible.
5. ADR format: title, status, date, context, options, decision, consequences. For stubs, fill the question from section 27 of the plan and leave “decision” as the plan’s stated direction, status “accepted-in-principle, to be confirmed at implementation”.
6. English is the language of these technical docs (the Cursor pack is English). Persian terms appear in the glossary column.
7. The developer host is Windows 11 with Docker Desktop (WSL2). Containers remain Linux. Do not write ADRs or product docs as if the development machine were Ubuntu. ADR-008 is still about single-server **deploy** limits, not about changing the Modular Monolith or switching images to Windows containers.

## Acceptance criteria

- A new reader can state the main order path, the four roles, the state machine, and v1 non-goals without inventing synonyms.
- Every identifier used here matches `AGENTS.md`.
- `ADR-001` explains why v1 is not microservices and which module boundaries must be kept.
- OPEN DECISIONS are listed, not filled in with invented values.
- No application code is required for T01 to pass, but the docs must be ready for T02 to scaffold the same module names.

## Tests required

None executable. Review by reading: consistency of identifiers, no invented patch versions, no extra features.

## Out of scope

Repository scaffold, Docker, CI, Keycloak, schema tables, UI implementation. Do not start coding the domain model here beyond what documentation needs.
